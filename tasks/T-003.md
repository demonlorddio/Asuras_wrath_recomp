## Why
Option D's biggest unknown is *what the native layer must implement* (D2:
~150 VSH libraries). Instead of guessing, extract the ground truth: link the
already-compiled x86-64 objects, read the undefined-symbol table, classify it.
This output is what Omnirush's swarm consumes when it's back.

## Inputs (read-only)

  (also inside `$PPUMOD` if the container is easier to enumerate via the manifest)

## Steps
1. Scratch dir `re/link/` (gitignored): gunzip all 225 objects (keep a copy of
   one to sanity-check it's a valid x86-64 ELF relocatable).
2. `llvm-link -o all.o *.o` (record any flags needed: relaxations, section
   handling — if it chokes, document exactly what breaks; that's a D1 finding).
3. `llvm-nm -u all.o` → sort/uniq → `re/imports.txt`.
4. Classify every import into: (a) PPU import namespaces (libkernel/libfs/
   libnet/libaudio/… — the syscalls we must implement natively in D2),
   (b) standard x86-64 C runtime (libc/libm — linkable on host), (c) unknowns
   (needs fork-source archaeology). Produce `docs/D2-tasklist.md`: one section
   per library namespace with symbol counts + representative symbols.
5. Note every D1 bootstrap issue found (link failures, local-model relocations
   that assume PPU memory layout, etc.) — those become D1/D5 task specs.

## Acceptance

## Report (Freebuff, 2026-11-09, branch `T-003`)

**Done.** 225 objects linked into one relocatable ELF; 480 undefined symbols,
each exactly once; classified into `docs/D2-tasklist.md` (52 lv2 syscalls in 11
namespaces + 417 unresolved PPU vaddrs + 9 runtime intrinsics + 2 trampoline).

### Findings

1. **`llvm-link` cannot do this job.** The 225 objects are *ELF x86-64
   relocatables*, and `llvm-link` only accepts LLVM bitcode — it fails with
   `expected top-level entity` on the ELF magic. The correct tool is
   **`ld.lld -r`** (LLD 23.1.4 is installed). Task text updated in effect: step 2
   is a relocatable link, not a bitcode link.
2. **`--allow-multiple-definition` is required.** Each object carries its own
   copy of the runtime shim `__resolve_symbols`; exactly 3 objects define it
   (all 74 bytes). Without the flag `ld.lld -r` aborts:
   `duplicate symbol: __resolve_symbols`. With it, the merged object keeps one
   definition — safe *if* the three copies are identical (equal size now; byte
   comparison is the remaining check).
3. **The import surface is small and clean.** 480 undefined symbols total:
   52 lv2 syscalls, 9 runtime intrinsics (`__ldarx`, `__lwarx`, `__stdcx`,
   `__stwcx`, `__get_tb`, `__check`, `__read_maybe_mmio32`, `__trap`), 2
   trampoline symbols (`__syscall`, `syscall_988`), and **417 `__0x<vaddr>`**
   references that no object defines.
4. **The 417 unresolved `__0x…` are the real D1 blocker.** They are named after
   the PPU vaddr they point at; the native link cannot close without either a
   stub or the missing recompiled bodies. Full list is in the tasklist doc.
5. **Numbers vs names don't fully line up yet.** The EBOOT has 66 distinct
   syscall numbers over 262 `sc` sites (`re/ppuanalyser/syscalls.csv`), while the
   objects name 52 lv2 entry points. That is expected — one named `sys_*` can be
   reached from several numbers/vaddrs and some numbers are unused — but the
   exact number↔name table is not in this checkout (`Emu/Cell/lv2` absent), so no
   mapping is asserted here. That is the one genuine TBD for D2, not a TBD in
   the work packages themselves.
