# T-003 — static link 225 objects → import inventory (D1 + D2 prep)

Status: pending · Owner: Freebuff · Priority: 2 · Effort: 1–2 days

## Why
Option D's biggest unknown is *what the native layer must implement* (D2:
~150 VSH libraries). Instead of guessing, extract the ground truth: link the
already-compiled x86-64 objects, read the undefined-symbol table, classify it.
This output is what Omnirush's swarm consumes when it's back.

## Inputs (read-only)
- 225 gzip x86-64 relocatable objects: `~/.cache/rpcs3/cache/BLUS30721/ppu-U4d6KieMMsKi2HjjqkGPE11XS3m2-EBOOT.BIN/*.obj.gz`
  (also inside `$PPUMOD` if the container is easier to enumerate via the manifest)
- host LLVM 23.1.4: `llvm-link`, `llvm-nm`, `llvm-objdump` (verify exact binary names/paths first)

## Steps
1. Scratch dir `re/link/` (gitignored): gunzip all 225 objects (keep a copy of
   one to sanity-check it's a valid x86-64 ELF relocatable).
2. `llvm-link -o all.o *.o` (record any flags needed: relaxations, section
   handling — if it chokes, document exactly what breaks; that's a D1 finding).
3. `llvm-nm -u all.o` → sort/uniq → `re/imports.txt`.
4. Classify every import into: (a) PPU import namespaces (libkernel/libfs/
   libnet/libaudio/… — the syscalls we must implement natively in D2),
   (b) standard x86-64 C runtime (libc/libm — linkable on host), (c) unknowns
   (needs fork-source archaeology). Produce `docs/D2-tasklist.md`: one section
   per library namespace with symbol counts + representative symbols.
5. Note every D1 bootstrap issue found (link failures, local-model relocations
   that assume PPU memory layout, etc.) — those become D1/D5 task specs.

## Acceptance
- one linked relocatable ELF object (committed path documented; file stays
  untracked if >10MB)
- `re/imports.txt` complete (every undefined symbol present exactly once)
- `docs/D2-tasklist.md` = ready-to-assign Omnirush work packages, no TBDs
