# T-002 — PPU disassembly pipeline (reproducible)

Status: done (Freebuff) · Owner: Freebuff · Priority: 1 · Effort: half-day–1 day

## Why
Phase 2 (real cheat addresses) and Option D both need a repeatable PPU
disassembly of EBOOT.BIN + the fork's PPUAnalyser function dumps. Host has NO
PPC binutils — use the fork's own tooling (see M4-COMPLETE.md in
/home/dio/Projects/ps3-recomp/rpcs3/games/asuras-wrath/ for exact flags).

## Inputs (read-only, see paths.env)
- `$EBOOT` — 10,629,688 B, `SCE\0` raw PPU program form, PPC32 plaintext from 0x400000
- `$FORK_BUILD` (rpcs3 binary) — supports `--ppumod-verify` / PPUAnalyser dumps
- `$FORK_SRC` — PPU disassembler source if CLI flags don't suffice

## Steps
1. Figure out the `SCE\0` container layout (read the fork's Elf reader code —
   `rpcs3/Emu/Cell/PPU` + `Utilities` ElfReader paths) → write a small
   `scripts/extract_ppu_segs.py` (run with `-I`, args-only) that dumps the LOAD
   segments to `re/disasm/seg_<vaddr>.bin` + `segs.json` (vaddr/len list).
2. Verify the PPU-hash: recompute SHA1 per segment as PPUModule.cpp does
   (sha1_update vaddr(8B) + memsz(8B) + segment bytes, then finish) → must equal
   `83096111daff850cc92b637aec1780c4079e1c58`. Write result to `re/ppu-hash.txt`.
3. Disassemble segments with whatever PPU disassembler the fork exposes
   (`--ppumod-verify` dumps, PPUAsm, or PPUAnalyser JSON); land outputs in
   `re/disasm/` (text) and `re/ppuanalyser/` (JSON dumps).
4. Build a symbol map: function census (39,254, from the manifest's
   function_census) ↔ disassembly ↔ PPUAnalyser names.

## Acceptance

## Report (Freebuff, 2026-11-09, branch `T-002`)

**Done.** Hash MATCH, both LOAD segments disassembled instruction-for-instruction,
function map + syscall/import census delivered. No fork-source archaeology was
needed: LLVM 23.1.4 on this host registers the `ppc64` target, so `llvm-objdump`
is the disassembler.

### Findings

1. **EBOOT is a full ELF64 BE PPC64 image at vaddr 0x10000.** The ELF header and
   the 8 program headers are *mapped into the image* (PH0: `off=0, vaddr=0x10000,
   filesz=memsz=0x1920de8`). PH1 is `0x1940000` (`filesz=0xaea80`, `memsz=0x27c598`, RWX).
   `e_shoff=0x19e1d98` lies past EOF: **section headers are absent**, so there is no
   `.symtab`, `.shstrtab`, or `.lib.stub` anywhere we can read. Two consequences:
   no symbol *names*, and no import-name table — only syscall numbers.
2. **The manifest's `function_census` is not a list of addresses.** Its 39,254
   entries are 16-byte-strided table offsets (`0x0 .. 0x9f810`), i.e. cache-record
   offsets inside the ppumod, not PPU vaddrs. Correcting the task's assumption.
   The real function count comes from the code: **39,248** canonical PPC64
   prologues (`mflr r0` = `7c 08 02 a6`), within 6 of the manifest's
   `function_count` (39,254) — 99.98% agreement.
3. **`e_entry = 0x1994138` is not code.** It lands in seg1 on a table of
   8-byte pointer pairs (`0x00961ca0 0x019af8f8 …`); seg1 has **zero** prologues
   and exactly one `bl`. Treat seg1 as data, not text.
4. **Import surface:** 262 `sc` sites, 249 with the preceding `li r11, <n>`
   decoded, **66 distinct syscall numbers**. Top: `403`×20, `141`×15, `130`×15,
   `182`×12, `44`×11, `129`×11. As expected for libkernel-heavy code
   (threads/FS/memory), not a game-specific import wall.
5. **Address calibration matters.** First pass wrapped the segment 0x40 bytes
   off (file offset 0 placed at `vaddr+0x40`), shifting every address by +0x40.
   Caught by cross-checking a `sc` site against the binary; rebuilt with
   `vaddr = file_offset_base` and re-verified (syscall at `0x8790c0` in both
   `re/ppuanalyser/syscalls.csv` and `re/disasm/seg0.txt`).

### Limitations / handoff to T-003 + T-004

- Function starts are **prologue-derived**: leaf functions without `mflr r0` are
  missing, and `size` means "distance to the next prologue", so it absorbs
  trailing data at the end of a dense cluster (largest gap: 3.3 MB). Sizes are
  good for local context windows, not for exact function extents.
- No symbol names are recoverable from these images. Labels are `sub_<vaddr>`;
  naming requires the original SELF/PRX import tables or rpcs3's syscall table
  (not present in this fork checkout — `Emu/Cell/lv2` is absent).
- T-004 can now use `re/disasm/seg0.txt` for ±32-instruction context around any
  `.rodata` hit, and `functions.csv` to attribute a candidate to a function.
- The PPU-hash key is `PPU-83096111daff850cc92b637aec1780c4079e1c58` (MATCH);
  per Agnes's MSG-0002 Q3, vaddrs survive a ppumod rebuild but the key changes —
  candidates must cite the hash they were found under.
