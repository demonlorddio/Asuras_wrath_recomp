# T-006 — cheat-slot candidates: reachability first

Status: in_progress (Freebuff) · Owner: Freebuff · Priority: 1 (user-facing) · Effort: multi-session

## Why
Six slots have no address: `skip_intro`, `one_shot`, `heavy`, `burst`, `god`,
`extras`. The user asked directly for working cheats (MSG-0021), so this is
User-priority, not backlog. T-004's `.rodata` sweep is already negative for
these, so the question this task answers first is **which of the six are
reachable at all, and by what mechanism** — before any address is named.

Deliverable per slot: either a candidate address with the evidence chain that
produced it, or a documented "not reachable this way, here is the mechanism
that would be" so Agnes never wires a guess (root cause R4).

## Hard rules
- Repo-local only: `re/`, `docs/`, `scripts/`, `tasks/`.
- No fabricated addresses. An address ships only with its derivation.
- Code patches are acceptable in the runtime engine (Phase 1 proved the
  `.text` no-op at `0x8a9458` applies cleanly); D-line bake caveats apply later.

## Report (Freebuff, 2026-11-10) — reachability census, P2 answer

Branch `T-006`. Evidence: the two LOAD segments (`seg_000000010000.bin`,
26.3 MB; `seg_000001940000.bin`, 715 KB), `re/ppuanalyser/*`,
`re/candidates.csv`, `re/imports*.csv`, `re/references.csv`.

### 0. P2 answer (MSG-0021 Q1), from the listing

`0x8a9438` holds **1,000,000.0f** (bytes `49 74 24 00`) and is read by exactly
**one** instruction — `lfs 2, 0(3)` at `0x8a9470`, inside the sleep helper:

```
8a9464: lis 3, 139 ; addi 3,3,-27592   -> 0x8a9438
8a9470: lfs 2, 0(3)
8a9478: fmuls 1, 1, 2                  -> microseconds
8a947c: fsub ... fsel ... fctidz       -> round half up via 2^63 @ 0x166c9b8
8a9494: cmpldi 3, 30 ; li 3,30         -> 30 us floor
8a94a0: li 11, 141 ; sc                -> sys_timer_usleep
```

Consequences, all checkable:

* **It is not title-only.** One reader in the shared helper means halving it
  scales *every* one of the 70 sleep call sites: title, menus, gameplay, IO and
  load waits. It cannot distinguish a title loop from an action loop.
* **It does not supersede `0x19afbac = 60.0f`.** Different mechanisms: that
  float is the frame-rate *target* consumed by the engine loop; `0x8a9438` is
  only the seconds→µs scale for waits. Keep both.
* **500000.0 is the right value**, but for a reason worth stating: it makes the
  round trip of a `sleep(1/30)` exactly `16667 µs`, i.e. one 60 fps frame. It is
  correct because the paced sleep is 1/30, not because 5e5 is special.
  Anything else pacing with a different constant gets doubled in rate — the
  in-game symptom to watch is any animation/audio that runs 2× fast.
* Watch item: halving genuinely-needed IO waits is what makes loads shorter but
  riskier. If a load breaks, the fix is to patch the *specific* frame-budget
  call site (the caller hunt below), not to revert the rate.

### 1. The shipped build has no cheat hooks — this is the big finding

UE3 serializes UnrealScript function names into the cooked binary, and they are
all here: **2,396** `<Class>exec<Func>` records survive. The CheatManager's
complete shipped set is:

`execDumpCoverStats`, `execVerifyNavMeshCoverRefs`, `execPrintNavMeshObstacles`,
`execPrintAllPathObjectEdges`, `execDrawUnsupportingEdges`,
`execVerifyNavMeshObjects`, `execLogParticleActivateSystemCalls`,
`execLogPlaySoundCalls`

That is nav-mesh debugging only. A targeted scan for
`God|Ghost|Ammo|Cheat|Unlock|Skip|Infin|Damage|Health|Invinc|Burst|Heavy|OneHit`
across all 2,396 records returns **no** `execGod`, `execGhost`, `execAllAmmo`,
`execToggleGodMode`, or any gameplay cheat — the only `Unlock*` hits are
`UBCGameEngineexecUnlockAchievement(s)` (trophies) and
`UBCOnlineSubsystemPCexecUnlockAchievement`.

**Consequence: `god` and `one_shot` cannot be done by triggering a cheat
function — no such function exists.** Any console-style "type God" route is
dead on this disc, and so is any patch that would flip a cheat-enabled flag,
because there is no cheat subsystem to enable. They have to come from the
damage path itself (§3).

## Report (Freebuff, 2026-11-10, second pass) — the disc's script packages answer the reachability question

Evidence: `BCGAME/COOKEDPS3` on the disc has **2,230 packages** — 2,198 `.XXX`,
`GLOBALPERSISTENTCOOKERDATA.UPK` (25.9 MB) plus the `.TFC` texture caches.
The UPK is the one carrying the class/export/name tables (engine classes
included), and it contains `BCPawn_Player`, so it is the file that defines the
gameplay API. `grep -rl BCPawn_Player COOKEDPS3` hits only the UPK.

### 0. Correction to §1 of the first report

"No cheat hooks" stands for the *console/exec* route — there is no `execGod`.
But the game **does** have god mode, as its own state. §1 never looked for it
because it only scanned `exec` records:

```
BoolProperty BCGame.BCPlayerController:bPlayerGodMode
BoolProperty BCGame.BCPlayerController:bEnemyGodMode
BoolProperty BCGame.BCPlayerController:bAlwaysHealthMax
BoolProperty BCGame.BCTypes:ExDamageInfo.bIgnoreGodMode
BoolProperty BCGame.BCTypes:ExDamageInfo.bDisableDie
Function      Engine.Controller:OnToggleGodMode      BoolProperty Engine.Controller:bGodMode
Function      Engine.Pawn:InGodMode                  Class       Engine.SeqAct_ToggleGodMode
Function      Engine.CheatManager:God
```

`ExDamageInfo.bIgnoreGodMode` is the important line: the game's own damage
struct has a field to *bypass* god mode, which means damage processing consults
it. God is therefore a real branch in this build, not an absent feature.

### 1. The damage path, by name

```
BCPawn:BCTakeDamage -> BCTakeDamageCore -> BCTakeDamageCoreReaction
BCPawn:CanBeTakenDamage        BCpawn:AdjustDamage      BCPawn:AddHealth(Val)
BCPawn:ChangedHealth           BCPawn:GetParamCorrect_DamageRate
BCPawn:GetParamCorrect_MaxHealthRate
Player overrides BCTakeDamageCore; enemy side is the one_shot hook:
BCPawn_Enemy:TakeDamageGetBaseDamageAmount -> TakeDamageModifyApplyDamage
             -> TakeDamageModifyDamageInfo      (MaxHealthOfEnemy, CheckEnemy_0_Health,
             bToNearDeathInDeathDamage, TakeDamageDead)
```

- **god** — the guard is a read of `bPlayerGodMode` (or `InGodMode()`), and
  `CanBeTakenDamage` / `BCTakeDamageCore` are where it must be.
- **one_shot** — `TakeDamageGetBaseDamageAmount` / `TakeDamageModifyDamageInfo`
  on the enemy are where the multiplier and the "0 health" branch live. Note
  `bToNearDeathInDeathDamage`: the game has a near-death path that may swallow a
  lethal hit, so a multiplier alone may not kill; the `CheckEnemy_0_Health`
  branch is the one to verify.

### 2. burst and heavy now have names, not just descriptions

- **burst** — `BCPawn_Player:UnlimitedModeGaugeVal` / `UnlimitedModeGaugeValMax`
  (float fields), with `AddUnlimitedModeGaugeValue`, `GetUnlimitedModeGaugePer`,
  `GetUnlimitedGaugePer`, `IsCanBurst`, `IsMaxMantraGauge`, `GetMantraGaugeVal/Max`.
  It is a gauge, per pawn, updated per frame — no constant to halve. The patch
  target is the *gain* (`AddUnlimitedModeGaugeValue`) or the `IsCanBurst` gate.
- **heavy** — `BCPlayerController_HeavyShoot` really is its own PlayerController
  class, so the heat-sink state is a field on it
  (`CancelHeatSinkCoolingMaterial`, `BurstButtonNameTag`, `GaugeProviders`).

### 3. Mechanism consequence — the blocking question

These are **object fields**, not constants. A static PPU memory patch (what
`CHEAT_LINES` can express) cannot set a field on a heap object, and the bytecode
that reads the field lives in the **UPK**, which is a game file we must not
patch or ship. So each of these four slots resolves to one of:

1. a **native** consumer inside the module that we can force (e.g. if
   `BCPawn:BCTakeDamageCore` or `CanBeTakenDamage` is native rather than
   UnrealScript, its guard is PPU code and is patchable); or
2. **script-only**, i.e. reachable only by editing the script package — which
   changes the shipped build and is out of bounds; or
3. a **field write** that needs a runtime hook the launcher does not have.

Next step is therefore a classification, not a search: parse the UPK export
table and report, per function above, `iNative` and `ScriptBytecodeSize`. Native
=> continue with a PPU trace on that exact function. All-script => the slot is
script-package territory and we tell the user that instead of patching blind.
